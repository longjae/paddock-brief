# 개발 플랜

## 제품 목표

개인 사용자가 각 그랑프리 주말을 선택하고 아래 정보를 한곳에서 소비할 수 있게 한다.

1. 한국 시간 기준 세션 일정
2. 레이스 전·예선 후·레이스 후 공식 인터뷰와 영상
3. 인터뷰 한국어 요약과 주요 구간 타임스탬프
4. 주말 지정 타이어와 드라이버별 스틴트
5. 트랙맵, 순위, 간격, 플래그와 날씨

## 1단계 — 프로젝트 기반과 읽기 전용 데이터 (현재 골격)

- Next.js App Router와 FastAPI 모노레포
- Supabase 초기 스키마와 RLS
- 샘플 데이터 모드
- 캘린더, 대표 인터뷰, 타이어, 트랙맵 대시보드
- API 상태와 공급자 상태 표시

완료 기준: API 키 없이 프론트·백엔드가 로컬에서 실행되고 테스트와 빌드가 통과한다.

## 2단계 — 실제 캘린더와 영상 수집

- Jolpica/OpenF1 일정 어댑터
- YouTube 공식 채널 allowlist
- 채널 uploads 플레이리스트 증분 수집
- 제목 기반 GP·세션·출연자 분류
- 임베드 가능 여부 검사 및 관리자 수동 보정
- Supabase upsert와 중복 방지

완료 기준: 새 공식 영상이 자동으로 후보 목록에 들어오고 승인 후 GP 페이지에 표시된다.

## 3단계 — 인터뷰 요약·번역

- FIA Media Centre 문서 URL 수동 등록 또는 허가된 입력
- 화자·질문·답변 단위 구조화
- 한국어 F1 용어집
- AI 초벌 요약/번역과 검수 상태 관리
- 원문과 요약의 버전·해시 저장

완료 기준: 인터뷰별 한국어 핵심 요약과 타임스탬프가 영상 옆에 표시된다.

## 4단계 — 레이스 센터

- OpenF1 REST로 현재 세션 부트스트랩
- WebSocket/MQTT 소비기를 FastAPI 백그라운드 워커로 분리
- 위치, 순위, 간격, 스틴트, 피트, 레이스 컨트롤 상태 결합
- 최신 상태는 Redis, 장기 기록은 Supabase에 저주기 스냅샷 저장
- 브라우저에는 SSE 또는 WebSocket으로 초당 2~4회 전송

완료 기준: 한 세션 동안 재연결과 데이터 지연을 표시하면서 타이어와 위치가 갱신된다.

## 5단계 — 개인용 운영

- 수집 작업 스케줄러
- 데이터 공급자별 장애 격리와 마지막 성공 시각
- 비밀 키 관리
- Supabase 백업과 관측성
- 스포일러 방지 모드와 모바일 레이아웃

## 다음 개발 순서

### 이번 개발에서 완료

1. 라이브 타이밍 스트림에서 선수 위치와 차량 데이터를 함께 전달한다. 종료된 싱가포르 GP의 모바일 화면은 390px에서 순위·미니섹터·타이어·트랙맵·팀 라디오를 확인했다.
2. 공개 팀 라디오를 별도 GitHub Actions 작업으로 수집한다. F1 아카이브가 차단된 실행 환경에서는 OpenF1 목록과 제한된 음성 경로를 사용한다. 영어 자막과 한국어 번역을 Supabase에 저장한다.
3. 레이스 리플레이에 1·2·4·8배속, 피트·플래그 이벤트 표시, 최대 12개 캐시 항목을 추가했다. 싱가포르 GP 19랩의 실제 피트 표시를 확인했다.
4. 위켄드의 기사 상세 화면에 원문 발행일과 지난 보도 표시를 추가했다. 첫 화면의 최신성은 실제로 노출하는 기사 기준으로 판단한다.

### 이어서 할 일

1. **미국 GP 실제 세션 중 확인:** 실시간 위치·속도·순위가 함께 갱신되는지 검증한다. 휴대폰에서 미니섹터, 트랙맵, 라디오의 지연과 가독성을 다시 확인한다. 종료된 세션만으로는 이 검증을 끝낼 수 없다.
2. **화면을 닫아도 수집 유지 — 개선 완료, 실제 세션 검증 대기:** GitHub Actions가 15분마다 세션을 확인한다. 한 번 시작하면 세션 종료 10분 뒤까지(최대 4시간) 수집하고 약 15초마다 최신 상태를 저장한다. 직접 연결에서 45초 동안 저장할 새 데이터가 없으면 앱의 HTTPS 스트림으로 전환하며, 연결 중단 뒤 재접속한다. 오래된 데이터와 다른 GP는 저장하지 않는다. GitHub 예약 자체가 늦게 시작되는 문제는 남아 있으므로 무공백 수집을 보장하지 않는다. 이를 보장하려면 상시 워커 배포가 필요하다. 다음 실제 세션에서 시작 시각·저장 간격·복구를 확인한다.
3. **팀 라디오 자막·화자 구분:** 빈 자막은 `unavailable`로 저장해 반복 전사를 막는다. 새 자막은 화자 A/B와 시간 구간을 저장한다. 과거 자막은 수집 작업의 `backfill_speakers` 옵션으로 다시 분석한다. 실제 신원이 확인되지 않은 화자를 드라이버나 엔지니어로 추정하지 않는다.

### 2026-10-26 운영 보완

- 라이브 화면에 직접 수신/저장 기록/공개 기록, 마지막 수신 일시(KST), 기록 경과, 위치·차량 데이터 인원을 표시한다. 기록 경과는 방송과 비교한 지연 시간이 아니다. 종료된 세션은 수집 장애로 표시하지 않는다.
- 라디오 429 재시도와 저장 피드 대체 경로를 추가했다. 30초 초과 화자 분리에는 자동 분할을 적용했고, 미국 GP 로슨의 44초 음원을 영어·한국어·화자 17구간으로 저장하는 실제 작업이 성공했다.
- 미국 GP FP1~예선 각 22명, 결승 56랩·22명·타이어·자막 36건과 결승 2랩의 위치/차량 리플레이를 확인했다. 경기 중 실시간 위치 수신 및 모바일 실전 검증은 완료하지 않았다.
- 다음 실제 세션 확인: 시작 10분 전 수집 실행 여부 → 15초 저장 간격 → 브라우저 닫은 뒤에도 저장 → 연결 단절 후 복구 → 종료 10분 뒤 정상 종료. GitHub 시작 지연은 별도 기록한다.

### 2026-10-27 멕시코 준비 1·2번

- 상시 수집 감독 프로세스와 Mac LaunchAgent 설치기를 구현했다. 세션 확인·실패 재시도·정상 종료·비공개 상태 파일·저장 키 누락 거절 테스트를 추가했고 총 105개 테스트가 통과했다. 설치와 상태 확인 방법은 [LIVE_WORKER.md](LIVE_WORKER.md)에 있다.

### 2026-10-28 멕시코 준비 3·4번

- 미국 GP 운영 라이브 페이지를 1366×768, 1440×900, 1920×1080, 390×844, 360×800에서 점검했고 바깥 가로 넘침은 없었다. 상태 시각을 최소 11px, 라디오·레이스 컨트롤 본문을 최소 13px로 보완했다. 모바일 전환 버튼은 최소 44px이며 키보드 포커스를 표시한다. 이는 브라우저 화면 크기 점검이며 실제 Windows 기기나 경기 중 가독성 검증은 아니다.
- F1 YouTube 채널 ID를 공식 채널 메타데이터와 맞추고 맥라렌 주소를 `@mclarenracing`으로 수정했다. RSS 실패 시 Data API(키가 있을 때), 공식 채널 페이지 순으로 대체한다. 구형 영상 카드와 새 lockup 카드, 채널 신원·발행일·연도·중복·잘못된 상세 페이지를 검증한다. `Drivers React After` 제목 누락도 수정했다.
- `videos_only` 수동 수집 모드를 추가했다. 기사 수집·OpenAI 요약·자막 생성을 실행하지 않고 영상 메타데이터만 복구한다. 실제 GitHub 실행 40636373894에서 미국 GP 공식 영상 3건이 저장됐다. 그중 두 영상의 watch 페이지 신원이 확인되지 않아 공식 채널의 GP·연도 표기가 명확한 경우에만 외부 링크로 저장했다. 이 두 건은 부분 오류로 기록하며 날짜와 임베드 가능 여부를 추정하지 않는다. 수집 시각도 영상 발행일로 표시하지 않는다.
- 전체 테스트 112개와 프런트 빌드가 통과했다. 자막·한국어 요약의 전체 복구는 완료로 처리하지 않는다. 공개 자막/상세 메타데이터 제공 범위 및 실행 환경 제한이 남아 있다.
- 배포 후 운영 API와 인터뷰 영상 탭에서 3건 노출을 확인했다. F1 예선·결승 선수 반응 2건은 공식 외부 링크로 제공하며 발행일은 미확인 상태를 유지한다. 메르세데스 Austin Race Debrief는 발행일과 인라인 플레이어 정보를 제공한다. 긴 제목을 포함한 영상 화면도 모바일 360·390px 및 PC 1366·1440·1920px에서 바깥 가로 넘침이 없었다. 라이브 상태 시각은 운영 모바일에서 11px로 적용됐다.
- 별도 추가 과제: 팀 공식 기사는 맥라렌·메르세데스만 직접 수집하고 전체 팀이 기사 한도를 공유한다. 11팀 공식 소스 등록, 공정한 팀별 한도, 비경기 주간 수집, 팀별 누락 상태 표시가 필요하다. 이 확대는 아직 구현하지 않았다.
- 상시 워커의 로컬 저장용 키 등록 대기는 10/27과 동일하다. 10/29에는 라디오 실패 사례 보완과 콘텐츠별 수집 상태 표시를 우선 진행한다.

### 2026-10-29 멕시코 준비 5·6번
